All active todo tracking lives here, and only here. Source: `LXC-BRM-context/requirements.md` (in-repo copy of `LXC-BuildManager.pdf`), read against `LXC-BRM-context/decisions/decision-2026-08-16.md`.

No other BRM folder keeps a todo file. Work is broken into phases so it ships in reviewable slices instead of one big drop. Phases are built in order; a phase doesn't start until the one before it is at least functional.

`[x]` = built and verified. `[ ]` = not done yet. A box only gets checked when the matching code exists and runs — never for "planned" or "in progress."

### Phase 1 — Repository Input & Detection (requirements.md §1)
- [ ] Validate GitHub URL / local path format before accepting it (currently accepts any non-empty text; bad input only surfaces later, during scan).
- [x] Add a repo via a local folder picker (NSOpenPanel) or a pasted GitHub URL.
- [x] Scan the repo root for `/build`; show "No `/build` folder found" when missing.
- [x] Scan `/build/scripts/` for `.sh` files when `/build` exists; show "No build scripts found in `/build/scripts/`" when empty.
- [x] Convert each script filename into a readable label (`build-ios.sh` → "build-ios").
- [x] Persist the repo list to disk (JSON in Application Support) so it survives app restarts.
- [ ] Show "last accessed" date/time next to each repo in the sidebar (the data is tracked internally, just not displayed yet).
- [ ] Give "remove from history" a visible control — it only works today via right-click → Remove, not a button anyone would discover.
- [x] Support opening and switching between multiple repos in one session; each keeps its own discovered scripts.

### Phase 2 — Build Execution & Management (requirements.md §2)
- [x] Display each discovered script as a clickable command button.
- [ ] On click, run `bash /path/to/repo/build/scripts/script-name.sh` as a background subprocess, working directory = repo root.
- [ ] Stream stdout/stderr live, line by line, each line timestamped.
- [ ] Track status per build: In Progress (spinner), Success (✓ + duration), Failed (✗ + duration).
- [ ] Add a Cancel/Stop control; cancelling preserves partial output and sets status to "Cancelled".

### Phase 3 — Log Storage & Retrieval (requirements.md §3)
- [ ] Write a log file to `/build/logs/` per run: `build-YYYY-MM-DD-HH-MM-SS.log`, full stdout+stderr, plain text.
- [ ] View current (live) and past build logs from history.
- [ ] Monospace, terminal-style log view with per-line timestamps, scrollable.
- [ ] In-log search: highlight matches, show match count, next/previous navigation.
- [ ] Log filters: Errors Only, Warnings Only, Info Only.
- [ ] Export current log to Downloads (or chosen location) as `.log` or `.txt`.

### Phase 4 — Project & Build Overview (requirements.md §4)
- [ ] Show repo name, path/URL, connection status, and total builds run this session.
- [ ] List build commands with label, last-run time, and success/failure/never badge.
- [ ] Per-repo build history: script, timestamp, status, duration for every run.
- [ ] Compute success rate and average build duration per repo.
- [ ] Quick-stats cards: total builds this session, success rate, most recently run, last failed build.

### Phase 5 — Multi-Repository Support (requirements.md §5)
- [x] List all opened/recent repos; switching is instant, no loading screen.

- [ ] Keep build history isolated per repo (depends on Phase 4).
- [x] Add and remove repos.
- [ ] Pin/favorite repos and show pinned state prominently (pin toggle exists in the context menu; not surfaced anywhere else, e.g. sorting pinned repos to the top).

## Decision Overrides In Effect

1. Stack: native Swift/SwiftUI, not Tauri/Rust/React — every phase above is built natively.
2. Storage: `projects.json` under `LXC-BRM-build-release/` for repo/script config, not a generic local JSON path.
3. Any new PDF-vs-decision conflict gets recorded in `LXC-BRM-context/decisions/` before being built around.
