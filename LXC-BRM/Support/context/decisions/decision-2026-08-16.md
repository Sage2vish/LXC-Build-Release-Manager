# Decision Log - 2026-08-16

## Decisions

### 1. Native macOS app
- The build manager is a native macOS app, not React Native.
- The app is organized as an Xcode project under `LXC-BRM/`.

### 2. Initial workspace folder layout
- The original workspace used a `BRM/LXC-BRM-*` naming pattern.
- The build-release folder owns scripts, logs, and version output.
- The active todo file lives in `worklog/` instead of being duplicated across folders.

### 3. Dated todo naming — **superseded on 2026-08-18**
- The active worklog todo file name is `todo-2026-08-16.md`.
- Each note uses task, subtask, and tracking sections.
- **Superseded by [`decision-2026-08-18.md`](decision-2026-08-18.md):** dated todo and worklog
  files are retired. Tracking is one plan per area, indexed by `worklog/BRM-Plan-todo.md`.

### 4. Release output
- The release `.dmg` will be staged in `build-release/version/`.

### 5. Decision precedence
- If a PDF requirement conflicts with a recorded decision, follow the decision.
- Keep the conflict documented in context so it is visible later.

### 6. Todo centralization — **partly superseded on 2026-08-18**
- All active todo tracking lives in `worklog/todo-2026-08-16.md`.
- The shared, frameworks, build-release, and context folders do not keep separate todo files.
- **Superseded by [`decision-2026-08-18.md`](decision-2026-08-18.md)** in its first clause: active
  tracking now lives in the `Plan-*` files, indexed by `worklog/BRM-Plan-todo.md`. The second
  clause still holds — no other Support folder keeps a tracker.

### 7. Local release packaging
- The release script builds a local Release app with signing disabled for the staging flow.
- The resulting `.dmg` is created in `build-release/version/` so the artifact can be inspected or copied without changing the app runtime code.

### 8. View ownership and Xcode target hygiene
- A SwiftUI view and each domain model have exactly one canonical declaration in the app target.
- Sidebar views are separate source files; `ContentView` remains the application shell and state-composition point.
- Documentation and formatter/linter configuration files stay in the repository but are not app resources or Xcode source entries.

### 9. Support folder refactor
- `Support/` is the single non-app container inside `LXC-BRM/`; it replaces the ambiguous `BRM/` folder.
- Its children use plain role names: `build-release/`, `context/`, `frameworks/`, `shared/`, and `worklog/`.
- `LXC-BRM` remains the app and product identity only; it is not repeated as a support-folder prefix.
