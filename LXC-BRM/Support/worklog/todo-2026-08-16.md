## Known Gaps / Honest Caveats

1. **No GUI click-through testing yet.** Everything above was verified by compiling, reading the code paths, and checking scanner logic against a real test repo's `/build/scripts/` folder — not by clicking buttons in the running app. Worth doing before calling this release-ready.
2. **"Total Builds Run" is all-time, not session-scoped.** The requirements doc (§4.1) describes a per-session counter; this app persists history across restarts and counts everything, which is arguably more useful but is a deliberate deviation worth confirming with you.
3. **GitHub repos can be scanned but not built.** Running `bash` against a GitHub URL isn't possible without a local checkout, which the requirements doc doesn't fully address either — flagging it here as an implicit product decision.

## Decision Overrides In Effect

1. Stack: native Swift/SwiftUI, not Tauri/Rust/React — every phase above is built natively.
2. Storage: `projects.json` under `build-release/` for the config template; the live app's own recent-repos/history JSON lives in `~/Library/Application Support/LXC-BRM/`, not in the repo.
3. Any new PDF-vs-decision conflict gets recorded in `context/decisions/` before being built around.
