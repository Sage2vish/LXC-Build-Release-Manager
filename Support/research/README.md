# Research

**The reading file.** Every topic the project is thinking about, in one place. Open it, scan the
table, follow whatever is relevant.

Research is deliberately kept apart from [`../worklog/`](../worklog/README.md), which holds
delivery: plans, checklists and counts. Mixing the two is how speculation quietly becomes a
commitment nobody agreed to. Nothing in this folder is scheduled, counted, or promised — a topic
here is a question being explored, and it stays that way until it is agreed.

| | Worklog | Research | Context |
| --- | --- | --- | --- |
| Holds | What is being built | What is being considered | Why the project is shaped this way |
| Unit | `Plan-<Area>-todo.md` | One topic per file | Rules, architecture, decisions |
| Has tasks | Yes, counted | **Never** | No |
| Answers | "What is left?" | "Should we?" | "Why is it like this?" |

## How a topic works

A topic file opens with three lines the index reads:

```markdown
**Stage:** exploring
**Opened:** YYYY-MM-DD
**Question:** the one question the topic exists to answer
```

**Stage** is one of:

| Stage | Means |
| --- | --- |
| `exploring` | Thinking out loud. Options, constraints, and the reasons an idea might not survive them. |
| `proposal` | One option is recommended and is waiting on a decision. |
| `promoted → Plan-X` | Agreed and turned into a plan. The note stays for the reasoning behind it. |
| `parked` | Considered and set aside, with the reason written down so it is not reopened blindly. |

Beyond those lines, a topic file should carry the constraints any idea has to survive, the options
with honest trade-offs — including the ones not recommended — and the open questions that need a
human answer. What it must **not** carry is a checklist. No `[ ]` items live here; that is the line
that keeps research from turning into untracked debt.

## Promotion — research becomes delivery

Only when the idea is agreed, and never automatically:

1. Write `../worklog/Plan-<Area>-todo.md` with a boundary statement, a checklist, and a tracking
   table.
2. Add one line to the `AREAS` list in
   [`../build-release/scripts/update-plan-index.py`](../build-release/scripts/update-plan-index.py)
   so the plan index picks it up in the right place and order.
3. Set this topic's stage to `promoted → Plan-<Area>` and leave it in place. The thinking behind a
   decision is worth more later than it seems now.

## Starting a topic

Add `Support/research/<Topic>.md` with the three header lines and the question it exists to answer,
then run:

```sh
python3 Support/build-release/scripts/update-plan-index.py
```

The table above regenerates itself from the files on disk, so a new topic appears without anyone
editing this page.

Return to the [Support Handbook](../README.md), or the [plan index](../worklog/BRM-Plan-todo.md)
for work that is actually scheduled.
