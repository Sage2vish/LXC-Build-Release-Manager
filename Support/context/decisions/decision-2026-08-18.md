# Decision Log - 2026-08-18

## Decisions

### 1. The dated todo and worklog files are retired

- `worklog/todo-2026-08-16.md` and `worklog/worklog-2026-08-16.md` are deleted.
- This supersedes decision 3 ("Dated todo naming") and decision 6 ("Todo centralization") in
  [`decision-2026-08-16.md`](decision-2026-08-16.md).
- Reason: one dated checklist could not hold a product of this size. By the time eighteen plan
  files existed, the dated file was claiming ownership of tracking it no longer performed, and the
  dated worklog was repeating narrative the plans already recorded. Two files describing the same
  work is how a project starts lying to itself.
- Nothing was discarded. Every item was moved into the plan that owns the surface it describes;
  the mapping is recorded in `worklog/BRM-Plan-todo.md` under **Retired files**.

### 2. `worklog/BRM-Plan-todo.md` is the master index

- It is the single entry point to delivery tracking, and the only file allowed to see everything.
- It holds no tasks. It links every plan, mirrors each plan's own count, states where a new task
  goes, and maps each requirements section to its owning plan.
- A plan that is not linked from the index does not exist as far as the project is concerned.

### 3. One plan per area, named `Plan-<Area>-todo.md`

- `worklog/` contains only the master index, `Plan-*` files, this folder's README, and `assets/`.
- Each plan owns exactly one surface — a window region, a tab, a feature, or an engineering area —
  and opens with a boundary statement saying what it does not own.
- Work that spans two plans belongs to the one that owns the **visible surface**; the other links
  to it rather than restating it.

### 4. Narrative lives in the plan that owns the work

- There is no separate story file. What shipped is recorded in the owning plan, usually as an
  "Already shipped" list or a verification section.
- Cross-cutting evidence — build and test runs, measurements, what has actually been click-tested
  in the GUI — is collected in `worklog/Plan-QualityVerification-todo.md`.
- Release artifacts, staging, tagging and publication are owned by
  `worklog/Plan-ReleasePackaging-todo.md`.

### 5. READMEs route to the master index, not to a dated file

- The root `README.md`, `LXC-BRM/README.md`, the Support handbook, the Context README, and the
  build-release documents all link to `worklog/BRM-Plan-todo.md` when they need to point at
  current work.
- No document outside `worklog/` names an individual plan as *the* tracker; they name the index,
  and the index routes onward.
