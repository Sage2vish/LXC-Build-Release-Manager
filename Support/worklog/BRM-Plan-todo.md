## How the counts stay honest

Everything between the two markers above is **generated**, not typed. Counting by hand is how the
index came to claim 146/146 for a Build tab that actually held 163 items.

```sh
python3 Support/build-release/scripts/update-plan-index.py           # rewrite the tables
python3 Support/build-release/scripts/update-plan-index.py --check   # fail if they are stale
```

The script reads every `Plan-*.md` in this folder, counts `- [x]` against `- [ ]` — plus the
Preferences plan's older `X`/`V`/`D`/`P` markers, where `D` counts as pending because a
half-wired setting is not a delivered one — and rewrites only the generated region. The prose,
the routing table, the retired-file map and these conventions are hand-written and never touched.

`--check` runs in CI, so a plan whose counts move without the index following fails the build
rather than quietly drifting. Adding a plan means adding one line to the `AREAS` list in the
script; that list is also what fixes the order the plans appear in.

## Conventions

1. `[x]` only when the code exists, builds, and the behaviour was checked. Not for "planned".
2. When something cannot be finished, it stays `[ ]` with a note saying **why** — an unchecked
   box with a reason is worth more than a checked box that is not true.
3. Every plan carries a Tracking table with its own counts. The generated tables above are read
   from the checkboxes themselves, so the two must agree; when they do not, the checkboxes win.
4. The narrative of what actually happened lives in the plan that owns the work — usually an
   "Already shipped" list or a verification section. There is no dated worklog file; the
   cross-cutting evidence ledger is in
   [Plan-QualityVerification-todo.md](Plan-QualityVerification-todo.md).
5. Every file in this folder is named `Plan-<Area>-todo.md` and appears in the generated tables. A
   new plan is not real until it is added to the `AREAS` list in the index script.
6. When a plan changes a rule, an architecture boundary, or a product decision, update
   [`context/`](../context/README.md) in the same change.
